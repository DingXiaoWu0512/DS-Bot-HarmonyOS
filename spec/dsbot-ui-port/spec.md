# Feature Specification: DS Bot HarmonyOS UI 层全量移植

**Created**: 2026-11-15  
**Status**: Draft  
**Input**: User description: "检查项目并构建" → 用户确认"完整实现 UI 层"，参考原项目安卓 App（Fei2411/DS-Bot 仓库 `mobile/`，React Native 版）

## Overview

把 DS Bot 手机应用（React Native 版）的完整 UI 层移植到 HarmonyOS ArkUI：接通本项目已完成的业务层（`common/`：链路加密、团队状态、聊天状态、i18n、markdown、deep view）、平台层（`platform/Platform.ets`：安全存储、WebSocket、剪贴板、触感、生物识别、相册、扫码、深链）和应用状态层（`appstate/AppStore.ets`），实现入口页、配对、抽屉导航、聊天、等你处理、Bot/群管理、记忆/日程/文件夹/用量、旁聊、Bot 浏览器与设置全套屏幕，让鸿蒙手机可以配对并远程操控电脑上的 DS Bot 团队。同时修复存量代码中的全部 ArkTS 编译错误（约 85 处），使工程构建通过。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 启动与配对 (Priority: P1)

首次启动：App 读取本机身份与已配对电脑；没有电脑时进入配对页——引导用户在电脑端 DS Bot「设置 → 手机」出示二维码，本机扫码，或粘贴 `dsbot://pair` 配对链接完成配对；配对成功保存电脑并进入主界面。从系统相机/浏览器点开 `dsbot://pair` 深链时（冷启动 onCreate / 热启动 onNewWant），无论当前在哪个屏幕都拉起配对流程。配对失败给出明确错误（电脑未接受、连不上服务器、电脑端版本过旧等），可重试。

**Why this priority**: 配对是一切的前提；没有电脑连接，其余屏幕都没有数据。

**Independent Test**: 清除配对数据后启动 App，进入配对页；点「使用相机」可拉起扫码；粘贴链接可发起配对并看到成功/失败反馈。

**Acceptance Scenarios**:

1. **Given** 无已配对电脑，**When** 启动 App，**Then** 显示配对页（指引文案 + 「使用相机」扫码入口 + 「粘贴配对链接」输入 + 「配对」按钮）。
2. **Given** 配对页，**When** 点「使用相机」，**Then** 拉起系统扫码界面；扫得 `dsbot://pair` 链接后自动开始配对。
3. **Given** 配对页，**When** 粘贴配对链接并点「配对」，**Then** 发起配对；成功后保存电脑并进入主界面。
4. **Given** 已在主界面，**When** 系统打开 `dsbot://pair` 链接，**Then** 拉起新增电脑的配对流程，取消后回到原界面。
5. **Given** 配对失败（电脑拒绝/服务器不可达），**Then** 显示对应中文错误文案，可重试；已有电脑时可放弃新增。

### User Story 2 - 团队抽屉与导航壳 (Priority: P1)

配对后进入以聊天为基座的主界面：左侧可滑出抽屉（桌面版侧栏的移植）——顶部「DS Bot」标题、搜索按钮、新建菜单（创建新 Bot / 创建群聊）；「等你处理」行（有待办时显示数量角标）；Bot 与群聊列表（头像、名称、最后预览、未读标记）；底部设置入口。顶部 Header 显示当前聊天标题（可点击头像 pill 进入详情）、菜单按钮（带待办红点）、旁聊按钮（有活动会话的 Bot）；断线时显示「正在重新连接…」。App 记住上一次打开的聊天，启动直接进入；保存的聊天被电脑删除时回退到主 Bot。

**Why this priority**: 导航壳是所有屏幕的容器；团队列表是进入各聊天的入口。

**Independent Test**: 已配对状态下启动 App，直接进入上次的聊天；滑出抽屉看到完整团队列表、搜索、新建菜单与设置入口。

**Acceptance Scenarios**:

1. **Given** 已配对，**When** 启动 App，**Then** 直接进入上次打开的聊天（没有则进入主 Bot）。
2. **Given** 主界面，**When** 点菜单按钮或左滑，**Then** 抽屉滑出：标题、搜索、新建、团队列表、设置入口。
3. **Given** 有待办事项，**Then** 抽屉顶部显示「等你处理 + 数量角标」，Header 菜单按钮带红点。
4. **Given** 团队加载中或断线，**Then** 聊天区显示「连接中…/正在重新连接…」并提供跳转「电脑」设置入口。
5. **Given** 抽屉打开，**When** 在搜索框输入关键字，**Then** 团队列表按名称/角色实时过滤。
6. **Given** 上次打开的聊天已被删除，**When** 启动 App，**Then** 回退到主 Bot 聊天，不白屏。

### User Story 3 - 聊天 (Priority: P1)

私聊与群聊屏幕：消息列表渲染全部消息类型——Bot 气泡（markdown：粗体、列表、代码块、表格、公式）、用户消息（含照片）、事件行（来要工作/回复了/交回工作/停下了…）、步骤行（工具调用、思考时长）、轮次分隔、提问卡（选项/多选/自定义回答）、批准卡（等待你的批准/允许/拒绝）、密钥请求卡（填写密钥，值不回显）、浏览器交接卡、deep view（表格/表单/公式等按固定格式渲染，有深度与大小上限，不执行脚本不访问网络）、图片消息（本机照片先本地显示，电脑确认后替换）；上滑加载更早消息；底部输入框发送文本、添加照片（相册选择、压缩到长边 2048）；乐观发送（发送中/失败态、失败点按重试）；Bot 工作中显示「停止」按钮；前台收到提问/批准时顶部显示通知横幅（可在设置关闭），点击跳到对应聊天。

**Why this priority**: 聊天是应用核心价值——与 Bot 对话、看它工作、就地处理它的请求。

**Independent Test**: 打开任一 Bot 聊天，输入消息发送并收到回复；发送一张照片；上滑看历史消息；点停止中断工作。

**Acceptance Scenarios**:

1. **Given** 聊天页，**When** 输入文本并发送，**Then** 消息以发送中状态出现在列表，Bot 回复按 markdown 渲染。
2. **Given** 聊天页，**When** 点「添加照片」并选择图片，**Then** 照片压缩后随消息发送，列表先显示本地图片。
3. **Given** 消息发送失败，**Then** 显示「未发出，点按重试」，点按后重新发送且不重复。
4. **Given** 聊天页，**When** 列表滑到顶部，**Then** 加载并拼接更早的消息。
5. **Given** Bot 正在工作，**Then** 输入区显示「停止」按钮，点击后 Bot 停止。
6. **Given** Bot 发来提问/批准/密钥/交接卡，**Then** 卡片就地渲染并可操作（选项、允许/拒绝、填写密钥、去接管）。
7. **Given** 不在对应聊天页时收到提问/批准，**Then** 顶部横幅提示（开/关跟随设置），点击跳转。

### User Story 4 - 等你处理 (Priority: P2)

「等你处理」以面板聚合所有等用户的项，按类分栏：提问、批准、密钥、卡片、浏览器交接；每项显示来源 Bot/群与内容摘要，点击跳到对应聊天；支持就地快速作答（你的回答、允许/拒绝、填写密钥）；无待办时显示「没有要等你的事」。已关闭的问题/批准显示关闭态提示。

**Why this priority**: 离开电脑时的核心场景——所有需要你处理的事集中一屏。

**Independent Test**: 电脑端 Bot 发起提问后，打开「等你处理」看到该提问并作答，列表实时更新。

**Acceptance Scenarios**:

1. **Given** 有待办的提问/批准/密钥/交接，**When** 打开「等你处理」，**Then** 分类列出全部待办。
2. **Given** 某提问，**When** 就地选择选项并提交，**Then** 回答发出，该项从列表移除。
3. **Given** 无任何待办，**Then** 显示「没有要等你的事」。
4. **Given** 某批准已在电脑端处理，**Then** 该项显示「这项批准已经关闭了」的关闭态。

---

### User Story 5 - Bot 详情、编辑与新建 (Priority: P2)

Bot 详情页：头像、名称与角色、主 Bot 标识、模型与强度（可换，模型菜单选择）、状态（被凭据/余额阻塞时提示）、记忆入口、定时任务入口、工作文件夹、用量、浏览器、操作（发消息、编辑、复制、删除——二次确认「再点一次删除这个 Bot」）。编辑页：资料（名字、标签、形象/颜色、头像照片上传与移除、指令）、隐私（私有开关及说明）、权限预设。新建 Bot（名字、形象、指令、模型）；新建群聊（成员多选至少 2 个、管理员、共享指令、公告、谁来回答：管理员主导/全体轮流）。

**Why this priority**: 管理团队是「手机操控电脑 Bot 团队」的另一半。

**Independent Test**: 从聊天 Header 头像 pill 进入 Bot 详情；点编辑修改名字保存；从抽屉新建菜单创建一个新 Bot。

**Acceptance Scenarios**:

1. **Given** 聊天页，**When** 点击 Header 的头像 pill，**Then** 进入该 Bot 详情页，显示模型、记忆、日程等入口。
2. **Given** Bot 详情，**When** 点「编辑」改名并保存，**Then** 名称在团队列表与 Header 同步更新。
3. **Given** 抽屉新建菜单，**When** 选「创建新 Bot」填名字并创建，**Then** 新 Bot 出现在团队列表并可进入聊天。
4. **Given** 新建群聊，**When** 只选了 1 个成员就创建，**Then** 提示「至少选两个 Bot，管理员带领这个群」。
5. **Given** Bot 详情，**When** 点删除后再点一次，**Then** Bot 被删除；第一次点只显示确认提示。

---

### User Story 6 - 群聊详情与设置 (Priority: P2)

群详情/设置页：成员列表（数量、管理员标识、设为管理员、成员头像堆叠）、公告、共享指令、谁来回答（管理员主导/全体轮流）、删除群聊（二次确认）。

**Why this priority**: 群聊是团队协作的载体，需要可查看与可调整。

**Independent Test**: 进入任一群聊的群设置，查看成员与公告，修改「谁来回答」保存。

**Acceptance Scenarios**:

1. **Given** 群聊 Header，**When** 点击 pill，**Then** 进入群详情，显示成员、公告、共享指令。
2. **Given** 群设置，**When** 修改「谁来回答」为「全体轮流」并保存，**Then** 设置生效。
3. **Given** 群设置，**When** 点「删除群聊」两次，**Then** 群被删除并回到团队列表。

---

### User Story 7 - 记忆、日程、文件夹、用量 (Priority: P2)

记忆页：查看记忆条目（范围：团队记忆/各 Bot 记忆/群记忆）、问记忆、添加（范围/主题/内容）、移除（二次确认）。日程页：定时任务列表（频率中文描述、下次执行时间）、新建（标题、提示语、频率）、删除。文件夹选择：文件夹列表导航（上一级、进入、使用此文件夹）、路径直接输入、团队工作区。用量页：按 日/周/月 显示 Tokens 输入/输出与运行次数。

**Why this priority**: 这些是 Bot 详情/群详情的子页，完成管理闭环。

**Independent Test**: 从 Bot 详情进入记忆页添加一条记忆；进入日程页新建一个每天任务；进入文件夹页选择一个文件夹。

**Acceptance Scenarios**:

1. **Given** Bot 记忆页，**When** 添加一条记忆（主题+内容）并保存，**Then** 列表出现该条目。
2. **Given** 日程页，**When** 新建每天 9:00 的任务，**Then** 列表显示「每天 9:00」与下次执行时间。
3. **Given** 文件夹页，**When** 浏览并选择某文件夹，**Then** Bot 详情的工作文件夹更新。
4. **Given** 用量页，**Then** 显示今日 Tokens 输入/输出与运行次数。

---

### User Story 8 - 旁聊 Side (Priority: P2)

Bot 工作时的旁问通道：不打断任务，基于目前进展回答；入口在聊天 Header 的旁聊按钮；显示「正在回答…」、可取消、回答附「按目前的进展回答；没有运行任何东西」说明；保留历史旁聊（新的旁聊/历史问题列表）。

**Why this priority**: 侧问是 RN 版的特色交互，对齐体验。

**Independent Test**: Bot 工作中打开旁聊，提一个问题，收到「正在回答…」→ 回答内容。

**Acceptance Scenarios**:

1. **Given** Bot 有活动会话，**When** 点 Header 旁聊按钮，**Then** 进入旁聊页。
2. **Given** 旁聊页，**When** 提问，**Then** 显示「正在回答…」，随后显示回答与来源说明。
3. **Given** 正在回答，**When** 点取消，**Then** 取消该旁问并显示已取消。

---

### User Story 9 - Bot 浏览器 (Priority: P2)

查看某 Bot 的浏览器画面、接管（Take over）、交还（Give back）、回应浏览器等待卡（登录/验证/确认需要你时）。

**Why this priority**: 对齐 RN 版的浏览器遥控能力。

**Independent Test**: Bot 打开浏览器后，从 Bot 详情进入 Bot 浏览器页，看到画面并接管/交还。

**Acceptance Scenarios**:

1. **Given** Bot 有打开的浏览器，**When** 进入 Bot 浏览器页，**Then** 显示浏览器画面。
2. **Given** 已接管，**When** 点「交还」，**Then** 控制权交还 Bot。
3. **Given** Bot 无浏览器，**Then** 显示「这个 Bot 没有打开的浏览器」。

---

### User Story 10 - 设置全套 (Priority: P2)

设置页（面板形式，Done 关闭）：外观（跟随系统/浅色/深色）、语言（跟随系统/中文/English，即时生效）、应用内横幅开关、电脑列表（在线状态、切换、忘记——二次确认、添加一台电脑）、密钥（列表、新增、更新、删除；高权限操作需解锁）、模型服务商（列表/添加已知或自定义/移除/填 API key/查找模型）、连接器（连接状态、连接/断开/重试、令牌填写）、能力（MCP/技能/套件/本地命令：查看、保存、批准、删除）、团队用量、位置（数据位置）、更新和诊断（检查更新、诊断日志查看/清除/复制）、关于（版本、许可）。

**Why this priority**: 设置覆盖配对设备管理与高级配置，是完整应用的必要部分。

**Independent Test**: 打开设置切换深色模式，界面即时变深；进入「电脑」忘记电脑（二次确认）；进入「密钥」新增密钥触发解锁。

**Acceptance Scenarios**:

1. **Given** 设置页，**When** 外观切到「深色」，**Then** 全应用界面即时变深色并持久化。
2. **Given** 设置页，**When** 语言切到「English」，**Then** 全部界面文案即时切换为英文。
3. **Given** 电脑列表，**When** 点「忘记这台电脑」两次，**Then** 电脑被忘记，回到配对页。
4. **Given** 密钥/服务商 key 等高权限操作，**When** 未解锁，**Then** 先弹生物识别/锁屏解锁；取消则操作不发。
5. **Given** 高权限操作但设备未设屏幕锁，**Then** 提示「请先给这台手机设一个屏幕锁」。

---

### User Story 11 - 主题、i18n 与全局体验 (Priority: P2)

深浅色主题（本机外观偏好 + 跟随电脑团队主题/强调色）；zh/en 双语（含中英文日期时间格式）；发送成功/危险操作的触感反馈；复制到剪贴板；危险操作「再点一次确认」的统一交互模式；等待加载态与错误态全屏反馈。

**Why this priority**: 决定整体质感，是全量对齐 RN 的验收面。

**Independent Test**: 切换系统深浅色与语言，界面跟随；长按消息复制。

**Acceptance Scenarios**:

1. **Given** 系统切到深色且设置为跟随系统，**Then** 界面变深色。
2. **Given** 电脑团队设置了强调色，**Then** 手机端主题色跟随。
3. **Given** 中文环境，**Then** 所有文案为中文、日期为中文格式（如「11月15日」）。

### Edge Cases

- 电脑端身份变化或拒绝连接 → 手机拒绝连接并提示重新配对（「电脑没有接受这台手机…」）。
- 断线重连：页面显示「已断开/正在重新连接…」，重连后补齐状态；写操作不自动重试，避免重复发送。
- 保存的聊天被电脑删除 → 回退到主 Bot，不白屏。
- 高权限操作但设备未设屏幕锁 → 提示「请先给这台手机设一个屏幕锁」。
- Bot 卡片/消息内容是不可信内容 → 只按固定格式渲染，深度与大小有上限，不执行脚本、不访问网络。
- 配对链接无效/过期 → 明确错误提示。
- 发送的照片电脑端不支持 → 「这不是 DS Bot 能发送的照片」。
- 空团队（电脑上没有任何 Bot）→ 引导创建第一个 Bot。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在启动时读取本机身份、已配对电脑与偏好（主题/语言/横幅），并据此决定首屏（配对页或主界面）。
- **FR-002**: 系统 MUST 支持扫码与粘贴链接两种配对方式，并处理 `dsbot://pair` 深链（冷启动与热启动）。
- **FR-003**: 系统 MUST 提供以聊天为基座的导航壳：抽屉（团队列表/搜索/新建/等你处理/设置入口）+ 页面栈（详情类推送、表单类弹出/模态）。
- **FR-004**: 团队列表 MUST 展示 Bot 与群聊（头像、名称、预览、未读），支持搜索过滤，置顶/隐藏规则与 RN 版一致。
- **FR-005**: 聊天页 MUST 渲染全部 ChatItem 类型（bot/user/event/answer/view/divider/steps/closed/post/relay），支持发送文本与照片、乐观发送与失败重试、历史分页、停止 Bot。
- **FR-006**: 聊天页 MUST 渲染提问/批准/密钥/浏览器交接/deep view 卡片并支持就地操作；卡片按固定格式渲染且有深度与大小上限。
- **FR-007**: 「等你处理」 MUST 聚合全部待办（提问/批准/密钥/卡片/浏览器交接）分类展示，支持就地作答与跳转。
- **FR-008**: 系统 MUST 支持 Bot 与群聊的查看/编辑/新建/复制/删除，以及记忆、日程、工作文件夹、用量、浏览器子页。
- **FR-009**: 系统 MUST 提供全套设置：外观、语言、应用内横幅、电脑管理、密钥、模型服务商、连接器、能力、团队用量、位置、更新与诊断、关于。
- **FR-010**: 密钥、服务商 key、连接器、能力、更新等高权限操作 MUST 先经生物识别/锁屏解锁；未设锁时给出指引。
- **FR-011**: 系统 MUST 支持深浅色主题与团队强调色跟随、zh/en 双语即时切换、触感反馈、剪贴板复制、危险操作二次确认。
- **FR-012**: 系统 MUST 修复存量代码的全部 ArkTS 编译错误（AppStore、Platform、EntryAbility、demo/link/team/common 各文件，约 85 处）及 `main_pages.json` 页面注册问题，使 `devecocli build` 通过。
- **FR-013**: UI MUST 基于现有 AppStore（V2 状态管理）与 chat-state/outbox 渲染，不重复实现业务状态。

### Key Entities *(include if feature involves data)*

- **SavedComputer / PhoneIdentity**: 已配对电脑（主机设备 ID、名称、密钥）与本机身份；由 store-core 持久化。
- **TeamState**: 电脑端同步来的团队快照（bots、rooms、questions、views、secretRequests、connectors、capabilities、work/waiting、prefs、secrets…），按 revision 版本同步。
- **Bot / Room**: 团队成员（模型、形象、指令、私有性、主 Bot 标识…）与群聊（成员、管理员、公告、模式…）。
- **ChatItem**: 聊天行（14 种 kind；含图片引用、文件、问题答案、工具步骤、乐观发送状态 localImages/local）。
- **Question / Approval / SecretRequest**: 等你处理的三类待办。
- **Prefs**: 本机偏好（theme、banners、lang），跨页即时生效。

## Assumptions

- `common/`、`platform/`、`appstate/` 现有代码是业务事实来源；本次只修复其中的编译错误，不重新设计其 API。
- RN 版（Fei2411/DS-Bot `main` 分支 `mobile/`）为 UI 与交互对齐基准；文案以本项目 i18n 字典为准。
- 不提供演示团队入口；`DemoLink`/`DemoTeam` 代码保留但 UI 不可达。
- 端到端加密推送通知、电脑端 Host 模块、中转服务器均不在本次范围。
- 目标设备以手机为主，兼容平板；最低 SDK 版本按工程现状（26.0.0）。
- 聊天与团队数据全部在电脑端，手机不落库（除偏好与配对凭据）。
