# Feature Specification: 聊天页与全局移植一致性修复（chat-parity-fix）

**Created**: 2026-11-24  
**Status**: Draft  
**Input**: 用户报告「聊天页面里很多加粗的字体 APP 上看不到，原网页可以看见」，随后要求与原 RN 项目（E:\Dshbot\DS-Bot\mobile\src）全面对比功能性代码差异，并修复确认范围内的移植 bug。

## Overview

对鸿蒙移植版（DSHBot-Harmony）与 RN 原版进行全面功能对比审计后，修复其中 5 个 HIGH 级（用户可见的功能损坏）与约 16 个 MEDIUM 级「移植 bug 类」差异。核心问题（用户报告的加粗不可见）根因是：RN 中 `<Text>` 可合法嵌套 `<Text>` 实现行内富文本，而 ArkUI 的 `Text` 只允许 Span/ImageSpan/ContainerSpan 子组件，移植版将 strong/em/link/del 原样译成嵌套 `Text()` 后静默不渲染。其余修复项均为同类「RN 写法直译到 ArkUI 后失效」或移植时遗漏的逻辑。有意为之的行为差异（两步确认、返回键开抽屉、待办分类扩展等）不在本次范围内。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 聊天消息的行内样式与结构完整可见 (Priority: P1)

用户在聊天页查看 Bot 回复时，`**加粗**`、`*斜体*`、`~~删除线~~`、`[链接](url)` 必须与原网页/RN 版一样完整显示且样式正确；链接可点击打开。正文后紧跟的列表渲染为列表而非字面 `- 项目`；嵌套/缩进列表保持层级；多行消息保留换行；`my_var_name` 等下划线标识符原样显示；Setext 标题按标题渲染；含代码块/表格/图片的消息气泡按 RN 规则占满可用宽度。

**Why this priority**: 用户直接报告的缺陷；影响每一条含样式的消息，是最高频的用户可见问题。

**Independent Test**: 在聊天页查看含上述 markdown 结构的 Bot 消息，逐项比对渲染结果；点链接验证跳转。

**Acceptance Scenarios**:

1. **Given** 一条含 `**加粗**`、`*斜体*`、`~~删除~~`、链接的消息，**When** 打开聊天页，**Then** 全部文字可见，加粗为粗体、斜体为斜体、删除线带线、链接为主题色下划线，点击链接能打开系统浏览器。
2. **Given** 消息为「说明文字」后紧跟 `- 项目一`/`- 项目二`，**When** 渲染，**Then** 显示为一段文字加一个项目列表（带 • 标记），不出现字面 `- `。
3. **Given** 含嵌套列表 `- a` / 缩进 `- b` 的消息，**When** 渲染，**Then** b 作为 a 的子级缩进显示，不与 a 同级或压平。
4. **Given** 含单个换行的多行消息，**When** 渲染，**Then** 保留换行（与 RN 一致），不拼接成一行。
5. **Given** 含 `my_var_name` 的消息，**When** 渲染，**Then** 原样显示，下划线保留、无斜体、无字符丢失。
6. **Given** 含 `Title\n=====` 的消息，**When** 渲染，**Then** 作为标题样式显示，不显示 `=====` 字面。
7. **Given** 含代码块/表格/图片的 Bot 消息与用户消息，**When** 渲染气泡，**Then** 气泡按 RN 的 wide 规则占满可用列宽（用户消息：hasBlockContent；Bot 消息：hasBlockContent 或含图片）。

### User Story 2 - 图片查看器翻页正常 (Priority: P1)

多图消息点开全屏查看器后左右滑动，页码指示（n / N）随翻页更新，滑动到的图片会加载原图。

**Why this priority**: 多图消息是常见场景，当前翻页后页码冻结、原图永不加载。

**Independent Test**: 打开一条多图消息的全屏查看器，滑动 2~3 页，观察页码与清晰度变化。

**Acceptance Scenarios**:

1. **Given** 一条 3 图消息，**When** 打开第 2 张并滑动到第 3 张，**Then** 指示器显示 3 / 3，且第 3 张随后加载清晰原图。

### User Story 3 - 顶部通知横幅可点击跳转 (Priority: P1)

出现「需要你处理」的顶部通知横幅时，点击横幅能跳转到对应聊天。

**Why this priority**: 横幅是重要通知入口，当前点击完全无效。

**Independent Test**: 触发一条 question/approval 通知，在横幅消失前点击。

**Acceptance Scenarios**:

1. **Given** 横幅正在显示，**When** 点击横幅文字区域，**Then** 打开对应聊天且横幅消失。

### User Story 4 - 忘记电脑后正确断链 (Priority: P1)

在设置-电脑页对「当前连接中的电脑」执行忘记后，应用立即停止与其的链接并切换/降级到正确状态。

**Why this priority**: 当前忘记后幽灵链接保持在线，状态显示错误且隐私上不应继续连接。

**Independent Test**: 连接状态下忘记当前电脑，观察连接状态与页面跳转。

**Acceptance Scenarios**:

1. **Given** 已连接电脑 A（另存有电脑 B），**When** 忘记 A，**Then** 链接切换到 B 并重新连接。
2. **Given** 已连接唯一电脑 A，**When** 忘记 A，**Then** 降级到配对引导页，无后台残留链接。

### User Story 5 - 消息行内容变化即时刷新 (Priority: P2)

已渲染的消息行内容发生变化（补充图片/文件、时间戳更新等）时，无需滚动离开视口即可看到新内容。

**Why this priority**: 列表 key 不含内容导致更新被吞，属于数据正确性问题。

**Independent Test**: 构造消息刷新后新增文件/图片的场景，观察行内容更新。

**Acceptance Scenarios**:

1. **Given** 某消息行已显示，**When** 刷新后该消息补充了图片引用，**Then** 不滚动列表即可见图片网格出现。

### User Story 6 - 附件菜单不再撑大输入栏 (Priority: P2)

宿主同时支持发图与发文件时，点 + 弹出附件菜单不改变输入栏卡片高度、不推移输入行。

**Why this priority**: 当前菜单作为 Stack 子组件参与布局，撑高卡片并把输入行顶向屏幕底缘。

**Independent Test**: 在支持双通道的主机上打开附件菜单，观察输入栏布局。

**Acceptance Scenarios**:

1. **Given** 输入栏显示中，**When** 点 + 打开菜单，**Then** 输入栏高度与位置不变，菜单浮层显示。

### User Story 7 - 可复制文本与门禁可用性 (Priority: P2)

审批卡中的命令/代码可长按复制；能力（MCP/技能/包）删除需两步确认；设置密钥/能力/更新时，只注册了锁屏密码（无生物识别）的手机按平台能力提供回退或明确的错误提示；偏好设置数据损坏不再导致应用无法启动。

**Why this priority**: 数据安全（误删、崩溃砖化）与可用性（PIN-only 设备被完全锁死）问题。

**Independent Test**: 分别验证复制、删除确认、无生物识别设备上的门禁行为、以及损坏 prefs 的启动。

**Acceptance Scenarios**:

1. **Given** 一条待审批命令卡，**When** 长按命令文本，**Then** 可复制。
2. **Given** 能力管理页某能力，**When** 点删除，**Then** 第一次点击进入待确认态，再次点击才删除。
3. **Given** 未注册指纹/人脸但设有锁屏密码的设备，**When** 打开需要解锁的设置项，**Then** 按平台能力弹出凭据验证；若平台不向三方开放则显示准确错误说明（不误报「未设置锁屏」）。
4. **Given** 本地 prefs 数据被写坏，**When** 启动应用，**Then** 回退默认值正常启动，不进入死机错误页。

### User Story 8 - IM 页状态可见与侧边聊及时刷新 (Priority: P3)

IM 页显示每个连接的实时状态（已连接/重连中/连接失败+错误）并提供重试；各平台引导的「打开控制台」链接可点击跳转。侧边聊天在回答期间以约 1.5s 间隔轮询，回答流式及时显示。

**Why this priority**: IM 页状态缺失导致用户无法自助排障；侧边轮询死代码导致回答延迟最多 15s。

**Independent Test**: 观察 IM 连接状态文案与重试按钮；在侧边聊天提问观察回答出现速度。

**Acceptance Scenarios**:

1. **Given** 某平台连接失败，**When** 打开 IM 页该连接详情，**Then** 显示失败与错误信息，点「重试」重新连接。
2. **Given** 侧边聊天处于 answering 状态，**When** 等待，**Then** 约 1.5s 内出现新内容，而非等待 15s 兜底轮询。

### User Story 9 - 定时任务暂停判断修复 (Priority: P3)

定时任务页的「可暂停」判断不再因 NaN 恒为否；过期的一次性任务按设计不可暂停/恢复。

**Why this priority**: 纯逻辑 bug（Date.parse 传毫秒时间戳恒 NaN），影响端口附加功能的正确性。

**Independent Test**: 查看过期一次性任务行是否不再显示暂停控制。

**Acceptance Scenarios**:

1. **Given** 一个已过期（scheduledAt 早于当前时间）的一次性任务，**When** 查看其行操作，**Then** 不显示暂停/恢复控制。

---

### Edge Cases

- markdown 中 `**` 未闭合、跨行加粗、加粗内嵌套斜体/代码：按现有深度上限降级为纯文本，不丢字符。
- 列表项后紧跟空行再缩进正文（松散列表续行）：正文保留在列表项内。
- 行内 token 树深度超过上限：内容以纯文本完整显示。
- 横幅显示期间收到新通知：保持现有替换逻辑，点击命中最新目标。
- 忘记电脑时后台正在进行的请求：断链后请求失败路径走既有 offline 处理，不崩溃。
- prefs 损坏时既有身份/电脑数据：不受影响（本就走了带守卫的读取）。
- 双通道附件菜单在键盘弹起时打开：菜单浮层不被键盘遮挡输入行。
- DeepView、桌面偏好等有意差异项：不在本次范围，行为保持不变。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 聊天页 markdown 行内样式（strong/em/link/del）必须以 ArkUI 合法方式（Span 系样式）渲染，全部文字可见，样式与 RN 版一致（粗体 600、斜体、删除线、链接主题色+下划线+可点击打开 http/https/mailto）。
- **FR-002**: markdown 词法必须支持：列表标记行打断段落、嵌套/缩进列表保持层级、松散列表空行续行并入列表项、Setext 标题（`=====`/`-----` 下划线式）、`_` 不做词内强调。
- **FR-003**: 段内软换行必须保留为换行显示（与 RN 一致），不得折叠为空格。
- **FR-004**: 含块级内容（代码/表格等）或图片的消息气泡必须按 RN 的 wide 规则占满可用列宽（用户气泡：hasBlockContent；Bot 气泡：hasBlockContent 或含 imageRefs/localImages）。
- **FR-005**: 图片查看器 Swiper 必须在翻页时更新当前页状态，驱动页码指示与对应页原图加载。
- **FR-006**: 顶部通知横幅的点击必须可达（不得因命中测试设置禁用内部点击目标），点击后打开对应聊天并关闭横幅。
- **FR-007**: 忘记当前活跃电脑后必须重新解析活跃电脑并重建/关闭链接（切换到下一台或降级到配对页），不得保留与被删电脑的链接。
- **FR-008**: 聊天列表行 key 必须包含行内容签名（文本量、图片/文件数、戳、状态等），内容变化时同 key 行必须重新渲染。
- **FR-009**: 附件菜单必须以不参与输入栏尺寸计算的浮层方式呈现，打开/关闭不改变输入栏卡片高度与输入行位置。
- **FR-010**: 审批卡中的 detail.text/reason/detail.code 必须支持长按/选择复制（copyOption）。
- **FR-011**: 侧边聊天存在 answering 状态的条目时必须启动约 1.5s 的状态轮询，全部结束后停止。
- **FR-012**: 偏好设置读取必须对损坏 JSON 容错（回退默认值），不得阻断启动。
- **FR-013**: 解锁门禁在无已注册生物识别时必须探测平台凭据回退能力；平台不支持时返回准确错误文案，不得误报「未设置锁屏」。
- **FR-014**: IM 页必须消费宿主下发的连接状态（imStatus）并显示：已连接/重连中/连接失败（含错误）；失败态提供「重试」（调用 im-retry）。
- **FR-015**: IM 平台引导的外部链接必须渲染为可点击项并通过系统能力打开。
- **FR-016**: 能力删除必须使用与移植版其他危险操作一致的两步确认（DangerRow）模式。
- **FR-017**: Schedules 的 pausable 判断必须将毫秒时间戳按数值比较，过期一次性任务不可暂停/恢复。

### Key Entities

- **InlineToken / MdToken（现有）**: 词法单元，本次扩展其解析规则（段落-列表边界、嵌套列表、Setext、`_` 词内限制、松散续行）。
- **行内样式段（新增，纯数据）**: 将 InlineToken 树扁平化为带样式标志（粗/斜/删除线/等宽/链接）的文本段列表，供 Span 渲染。
- **rowKey 内容签名（现有函数扩展）**: MessageList 行 key 生成，加入内容指纹。
- **imStatus（类型扩展）**: IM 连接状态字段接入 types 与 IM 页。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户报告的加粗场景（原网页可见、APP 不可见）100% 复现于修复前、100% 消失于修复后；抽验斜体/删除线/链接同样可见可点。
- **SC-002**: 上述 17 项验收场景（US1~US9 全部 Acceptance Scenarios）逐条通过。
- **SC-003**: 修复涉及文件 `devecocli build` 通过、无新增 ArkTS 静态检查错误。
- **SC-004**: 有意差异项（两步确认、返回键、待办分类、DeepView 预选等）行为与修复前完全一致（无回归）。

## Assumptions

- 宿主协议（ds-bot 0.3.10）已具备 imStatus 下发与 im-retry 端点（桌面版已在消费）。
- HarmonyOS 对三方应用开放的用户凭据认证范围以实际 SDK 为准；若锁屏密码（PIN）认证不对三方开放，FR-013 以准确错误文案与探测结果为准，不强制实现 PIN 验证。
- 审计中标为「有意为之/更新上游」的行为差异（返回键开抽屉、待办分类扩展、任务列表 ☑ 字形、图片真实加载、表格 Copy/Expand、两步确认替代弹窗、Draft 切换清空、步骤行单工具文案、边缘滑动非跟手、DeepView 选项预选等）保持现状，不在本次修复范围。
- LOW 级外观差异（占位符样式、a11y 细节、键盘处理等）不在本次范围。
- 验证环境使用本机已有模拟器（Mate 90 Pro, HarmonyOS 7 / API 26）。

## Open Questions

- 无（修复范围已经用户确认：HIGH + 移植 bug 类 MEDIUM；行为差异项不改）。
